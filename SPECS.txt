  Key Design Decisions:
  • Offline-First: All data persisted to IndexedDB. No server dependency.
  • SPA Mode: SolidStart configured as Single Page Application (no SSR).
  • Fine-Grained Reactivity: SolidJS signals for instant UI updates.
  • Component Composition: Kobalte headless primitives + CVA for variants.

5. STATE MANAGEMENT
────────────────────────────────────────────────────────────────────────────────

Cart Store (src/stores/cart.ts):
  Global reactive store using SolidJS createStore.

  Type: CartItem = Product & {
    cartItemId: string;     // Composite: "productId-variantHash"
    quantity: number;
    basePrice: number;      // Original product price (before variant modifiers)
    selectedVariants?: { groupName, optionName, priceModifier }[];
  }

  Exported Functions:
  ┌──────────────────────────┬─────────────────────────────────────────────────┐
  │ addToCart(product, vars?) │ Add product; merge if same variant combo exists│
  │ updateCartItemVariants() │ Change variants on existing cart item           │
  │ updateQuantity(id, +/-1) │ Increment/decrement; remove at 0               │
  │ getCartTotal()           │ Computed sum of price × quantity                │
  │ getCartCount()           │ Computed sum of all quantities                  │
  │ clearCart()              │ Empty the cart                                  │
  └──────────────────────────┴─────────────────────────────────────────────────┘

  Cart Item ID Strategy:
    cartItemId = "{productId}-{sorted variant option names joined by '-'}"
    This ensures the same product with different variant selections becomes
    separate line items, while identical combos merge (increment quantity).

7. BUSINESS LOGIC
────────────────────────────────────────────────────────────────────────────────

Margin Calculation:
  marginPct = Math.round(((price - cogs) / price) * 100)

Margin Classification (4-Tier):
  ┌────────────────┬────────┬───────────────────┬─────────────────────────────┐
  │ Category       │ Range  │ Color             │ Meaning                     │
  │────────────────│────────│───────────────────│─────────────────────────────│
  │ Kritis         │ < 30%  │ Red               │ Risk of OPEX loss           │
  │ Tipis          │ 30-44% │ Orange            │ Minimum viable margin       │
  │ Sehat          │ 45-71% │ Emerald / Green   │ Ideal F&B industry target   │
  │ Optimal        │ ≥ 72%  │ Blue              │ Strong cash profit          │
  └────────────────┴────────┴───────────────────┴─────────────────────────────┘

  Note: Thresholds adjustable in getMarginStatus() in products.tsx.
  User updated Tipis to ≤44%, Sehat to ≤71% from the original 40%/69%.

HPP / COGS Computation:
  For each product:
    totalHPP = Σ (rawMaterial.costPerUnit × rawMaterial.quantity)

  At checkout (per cart item):
    unitCogs = product.cogs + Σ(selectedVariant.cogsModifier)
    totalCogs = unitCogs × quantity

  If no raw materials configured:
    fallback cogs = price × 0.45 (45% assumption)

Payment Processing:
  Payment Methods: TUNAI, QRIS, GOFOOD, GRABFOOD, SHOPEEFOOD

  For platform orders (GoFood, GrabFood, ShopeeFood):
    • originalAmount = cart subtotal (menu price)
    • totalAmount = platform net received (after commission/markup)
    • platformAdjustment = totalAmount - originalAmount
    • This delta represents platform commission or adjusted pricing

Receipt Number Generation:
  Format: "NP-{YYYYMMDD}-{incrementing 4-digit}"
  Example: NP-20260407-0042

Financial Report Calculation:
  ┌──────────────────┬──────────────────────────────────────────────────────┐
  │ Omset            │ Σ transaction.totalAmount (excluding adjustments)   │
  │ COGS Total       │ Σ transaction.cogsTotal                             │
  │ Gross Profit     │ Omset - COGS Total                                  │
  │ Platform Adj.    │ Σ (totalAmount - originalAmount) for platform tx    │
  │ Expenses         │ Σ expense.amount                                     │
  │ Net Profit       │ Gross Profit + Platform Adj. - Expenses             │
  │ Modal Return     │ COGS Total (capital to be reinvested)               │
  │ True Profit      │ Net Profit - Modal Return                           │
  └──────────────────┴──────────────────────────────────────────────────────┘

11. KNOWN LIMITATIONS & TECHNICAL DEBT
────────────────────────────────────────────────────────────────────────────────

  1. No Cloud Sync: Data lives only in browser's IndexedDB. Clearing browser
     data destroys all records. Multi-device support requires future cloud layer.

  2. No Service Worker: PWA capabilities (install prompt, offline caching of
     app shell) not yet configured despite offline-first data architecture.

  3. Stock Not Auto-Decremented: Sales do not reduce product.stock.
     Stock management is still manual.

  4. Permission Enforcement Partial: Role/permission system has CRUD UI but
     enforcement is limited to a few UI guards. No server-side auth.

  5. CartFloatingButton Monolith: At 768 LOC, this component handles cart
     display, payment flow, QRIS display, platform adjustment, and receipt
     generation. Should be decomposed.

  6. Receipt Number Non-Persistent Counter: Receipt numbers generated from
     in-memory counter per session, not globally unique.

  7. Image Storage: Product and QRIS images stored as Base64 in IndexedDB.
     Large images may impact performance. Should migrate to blob storage.

  8. No Test Coverage: No unit, integration, or e2e tests exist.
